# Dedicated engine manager acceptance

Choose Azwah Privacy Engine (QA) in a Chromium profile's runtime selector. Compatibility launches keep the old profile layout. The dedicated runtime has fresh persistent storage below the same Azwah profile root, in privacy-engine. Switching the selector does not convert cookies or touch Chrome Stable's store. Use the usual profile stop and launch controls to restart.

The source manager can point PM_PRIVACY_ENGINE_EXE at a locally installed QA engine. A deliberately built Ultimate QA bundle can include the isolated engine with AZWAH_PRIVACY_ENGINE_QA_BUNDLE=1 after building engine-prototype/out/win-unpacked. The standard Ultimate packaging configuration excludes the engine. The branch workflow installs the QA engine and drives it through the real manager API. It does not install the complete Ultimate desktop.

Location defaults to Auto for proxies. Auto uses the existing MaxMind configuration, verified public exit lookup and provider accuracy. Manual uses the saved coordinates and explicit accuracy. System applies no override. The engine uses a fixed proxy, with authenticated proxies relayed on loopback, and does not hand credentials to renderer processes. The Windows fixture covers authenticated HTTP via a local proxy. It does not establish public exit IP, regional GeoIP, HTTPS CONNECT, DNS, IPv6 or provider failure behavior.

The toolbar is a separate local renderer. Remote tabs receive no preload or Node integration. Certificates use Chromium's default checks. Native permission prompts are scoped to the tab and origin. QA loopback browsing is limited to source-launched fixture sessions. The installed engine remains unsigned QA software. Extensions, automation, bookmarks, history UI, downloads and crash tab restoration are outside this slice.
