# AZWAH capability parity audit (Phase 1)

Checked 2026-11-19 against `feature/azwah-ultimate-2` at `5e17aec`. Every row cites code in this repository. Competitor columns describe each vendor's own published documentation, not AZWAH behavior, and were not tested here.

## How statuses are assigned

| Status | Meaning |
|---|---|
| `verified` | A test exercises it and passes in one of PR #27's Windows gates: **Windows native build and validation** (`test:unit`, desktop, API, engine, proxies, security, UI smoke, Electron) or **AZWAH Windows installer acceptance** (Chrome Stable live, network and location tests, installed smoke, upgrade and update). |
| `implemented-unverified` | Code and tests exist, but those tests do not run in either Windows gate (for example `test:browser-runtime`, `test:m7`, `test:m8`). |
| `partial` | Works on some engines or paths only. |
| `unsupported-by-engine` | Stock Chrome, Chromium or Firefox has no supported control. Nothing is simulated. |
| `missing` | Not implemented. |

Priority means user benefit relative to cost: P0 next, P1 soon, P2 later or needs approval.
